## 基本概念

- 运算符（operator）：是指进行运算的动作，比如加法运算符“+”，减法运算符“-”，赋值运算符“=”。
- 算子（operand）：是指参与运算的值，这个值可能是常数，也可能是变量，还可能是一个方法的返回值

- 表达式（expression）：运算符和算子的组合，即为表达式

## 运算符

### 关系运算符

- 所有的关系运算符的优先级比算术运算符的低，但是比赋值运算符的高

- 判断是否相等的==和!=的优先级比其他的低，而连续的关系运算是从左到右进行的

- 短路：逻辑运算是自左向右进行的，如果左边的结果已经能够决定整体结果了，就不会做右边的计算（!, &&, ||; !的优先级比后两者高, 且基本上是单目运算符中最好的）

- 条件运算符（俗称三目运算符）是自右向左结合的（eg：`w<x?x+w:x<y?x:y`）

## 数组

### 函数参数表中的数组

```c
testArray(int nums[])
```

- 函数参数表中的数组实际上是指针
- sizeof(nums) == sizeof(int *nums)
- 但是可以用数组的运算符[]进行计算（计算下标位置）

---

- 数组变量本身表达地址，数组变量是特殊的指针
- 数组的单元表达（元素）是变量，需要使用&取的地址
- []运算符可以对数组做，也可以做指针做：`int *p=xxx; p[0]  <--> a[0]` （假设指针P指向的是数组，即按照数组地址的计算方式计算）
- 数组变量是const的指针，所以不能被赋值：`int a[] <--> int * const a`

## 指针

指针变量就是记录地址（内存地址）的的变量

> 这也在侧面说明了，C语言中参数传递的模式是值传递，而不是引用传递。在一些特需的情况下需要达成传递引用的效果，所以有了指针，使得整体的操作变得更加的灵活

### 运算符 &

用于获取变量的地址（内存地址），它的操作数必须是变量

### 运算符 *

是一个单目运算符，用来访问指针的值（即指针变量保存的内置地址）所表示的地址上的变量

### *p++

- 取出p所指的那个数据来，完事之后顺便把p移到下一个位置去
- *的优先级虽然高，但是没有++高
- 常用于数组类的连续空间操作
- 在某些CPU上，这可以直接被翻译成一条汇编指令

### 指针的类型转换

- void* 表示不知道指向什么东西的指针
    - 计算时与char*相同（但不想通，即仅计算原理相同）
- 指针也可以转换类型
    - `int *p = &i; void *q = (void*)p;`
    > 这并没有改变p所指的变量的类型，而是让后人用不同的眼光通过p看它所指的变量

## 字符串

- 以0（整数0）结尾的一串字符（0和'\0'是一样的，但是和'0'不一样）
- 0标志字符串的结束，但是它不是字符串的一部分（计算字符串长度的时候并不包含这个0）
- 字符串以数组的形式存在，以数组或指针的形式访问（更多的是以指针的形式访问）

### 字符串常量

`char *s = "Hello, World!";`

- s 是一个指针，初始化为指向一个字符串常量

    - 由于这个常量所在的地方（内存地址）比较特别，实际上s是`const char *s`，但是由于历史的原因，编译器可以接收不带const的写法
    - 但是试图对s所指的字符串做写入会导致严重的错误

> 字符串常量是只读的，不可修改，尝试修改（写入）会导致严重的错误致使程序崩溃！

- 如果需要构建可以修改的字符串，那么应该用数组：`char s[] = "Hello, World!";`

> 实际上，还是会在不可修改的地方先生成"Hello, World!"字符串，而后将其拷贝至程序栈中以数组构造，所以才表现出基于数组构造的字面量字符串可以被修改，因为实际上修改的是本地程序栈内存中的字符数组

> 本质上其实就是字符串常量的管理，我们通常将存放常量的地方称之为常量池。而字面量的方式生成的都是常量，所以实际上也会被常量池所管理。只不过使用数组存储的字面量，会先受到常量池的管理使得字面量可以成功创建，而后将字面量拷贝到本地程序栈的数组中（数组存储），所以修改的也是数组中拷贝而来的副本，常量池中的原字面量值是不可修改的。

#### 指针与数组的选择

- 如果要构造一个字符串 --> 使用数组
- 如果要处理一个字符串 --> 使用指针

## 结构类型

- 枚举 enum
- 结构类型 struct

### struct

```c
// 结构类型声明
struct point {
    int x;
    int y;
};

// 定义结构变量
struct point p1,p2;
```

常用表示
```c
struct point{
    int x;
    int y;
} p1, p2;

```

无名结构
```c
struct {
    int x;
    int y;
} p1, p2;

```

结构变量的初始化

```c
struct point p = {20, 30};
struct point p = {.x=20, .y=30};
```

- 和本地变量一样，在函数内部声明的结构类型只能在函数内部使用
- 所以通常在函数外部声明结构类型，这样就可以被多个函数所使用了
- 和数组不同，结构变量的名字并不是结构变量的地址，必须使用&运算符：`struct point * pPoint = &p1;`
---
结构作为函数参数
`int numberOfDays(struct date d)`
- 整个结构可以作为参数的值传入函数
- 这时候是在函数内新建一个结构变量，并复制调用者的结构的值
- 结构也可以作为函数的返回值

> 注意，这区别于Java中引用对象的传递表现。换句话说：结构变量并不等同于对象引用。在值传递的基础上，传递的到函数中的结构变量是一个完整的复制体。同时结构体变量间的赋值也是结构体值的完全复制，有别于对象引用的赋值。核心要点还是在于结构体变量不是指针！

--- 
指向结构的指针

```c

struct point * p = &p1;

// 以下两者等价
(*p).x = 20;
p->x = 20;

- 用 -> 表示指针所指的结构变量中的成员

```

### 类型定义 typedef

- C语言提供了一个叫做`typedef`的功能来声明一个已有的数据类型的新名字，比如：`typedef int Length;` 使得Length成为int类型的别名。
- 这样，Length这个名字就可以代替int出现在变量定义和参数声明的地方了

```c

typedef long int64_t;

typedef struct point_s {
    int x;
    int y;
} Point;

typedef struct {
    int x;
    int y;
} Point;

```

- 新的名字是某种类型的别名
- 改善了程序的可读性，比如struct在声明变量时就可以直接用别名而不用再写struct关键字了

## 程序结构

### 全局变量

- 定义在函数外面的变量是全局变量
- 全局变量具有全局的生存期和作用域
    - 它们与任何函数都无关
    - 在任何函数内部都可以使用它们

- 没有做初始化的全局变量会得到0值（本地变量并不会存在默认0值的情况）
    - 指针会得到NULL值
- 只能用编译时刻已知的值来初始化全局变量
- 它们的初始化发生在main函数之前

> - 不要使用全局变量来在函数件传递参数和结果
> - 且尽量避免使用全局变量
> - 使用全局变量和静态本地变量的函数是线程不安全的

### 静态本地变量

- 在本地变量定义时加上static修饰符就成为静态本地变量
- 当函数离开的时候，静态本地变量会继续存在并保持其值
- 静态本地变量的初始化只会在第一次进入这个函数时做，以后进入函数时会保持上次离开的值

--- 

- 静态本地变量实际上是特殊的全局变量
- 它们位于相同的内存区域
- 静态本地变量具有全局的生存期，函数内的局部作用域

### 返回指针的函数

- 返回本地变量的地址是危险的
- 返回全局变量或静态本地变量的地址是安全的
- 返回在函数内malloc的内存（内存地址）是安全的，但是容易造成问题
- 最好的做法是返回传入的指针

### 编译预处理指令

- #开头的是编译预处理指令
- 它们不是C语言的成分，但是C语言程序离不开它们
- #define用来定义一个宏

#### 宏

- 定义：#define <名字> <值>
- 注意没有结尾的分好，因为不是C的语句
- 名字必须是一个单词（合法的变量名称声明），值可以是各种东西
- 在C语言的编译器开始编译之前，编译预处理程序（cpp）会把程序中的名字换成值
    - 单纯的、完全的文本替换

---

带参数的宏

- 一切都要有括号
    - 整个值要括号
    - 参数出现的每个地方都要括号
- #define RADTODEG(x) ((x) * 57.29578)
- 可以带多个参数
    - #define MIN(a,b) ((a)>(b)?(b):(a))
-也可以组合（嵌套）使用其他的宏
- 在大型程序的代码中使用非常普遍
- 但是宏没有类型检查，存在类型检查的情况可以参见inline函数
 
- gcc --save-temps    可以看到编译过程中的临时文件 .i的就是预处理后的文件

> 宏的编译预处理就是单纯的文本替换

### 大程序结构（工程化）

#### 头文件

- 把函数原型放到一个头文件（以.h结尾）中，在需要调用这个函数的源代码文件（.c结尾）中#include这个头文件，就能让编译器在编译的时候知道函数的原型
- #include是一个编译预处理指令，有两种形式来指出要插入的文件
    - "" 要求编译器首先在当前目录(.c文件所在目录)寻找这个文件，如果没有，到编译器指定的目录去找
    - <> 让编译器只在指定的目录去找
    - 编译器自己知道自己的标准库的的头文件在哪里(如unix：/usr/include/)
    - 环境变量和编译器命令行参数也可以指定寻找头文件的目录
- 在使用和定义这个函数的地方都应该#include这个头文件
- 一般的做法就是任何.c都有对应的同名的.h，把所有对外公开的函数的原型和全局变量的声明都放进去

*#include的误区*

- #include不是用来引入库的（当不做头文件的引入，也是可以编译通过的。实际上是因为编译器会猜测参数类型，猜对了执行就是正确的，否则就会出现异常情况，比如计算错误，或者崩溃）
- stdio.h里只有printf的原型，printf的代码在另外的地方，某个.lib(Windows)或.a(Unix)中

- #include<stdio.h>只是为了让编译器知道printf函数的原型，保证你调用时给出的参数值是正确的类型

### malloc得到的空间是连续的吗？

问题：相邻两次malloc得到的空间是否是连续的呢？你得到的空间的实际大小是否就是你要求的大小呢？如果你malloc零长度会得到什么结果呢？

https://www.icourse163.org/learn/ZJU-200001?tid=1471612444#/learn/content?type=detail&id=1256792027&cid=1289918081&contentid=1334407352
答案：不连续，最小分配32字节。且多次运行发现，每次连续两个malloc分配的地址16进制低三位不变，而高三位随机变化，这是因为操作系统是按页管理内存的，一页一般为4KB，即对应16进制的三位数，所以合理猜测每次运行都被分配到了不同的页。如果分配0，发现相邻两个malloc分配的地址还是间隔32字节。
进一步发现的规律：需求小于等于24字节的话，会固定分配32字节的空间。一旦需求大于24字节，比如25字节，会多分配16字节空间，即48字节，但一旦需求字节数和48字节的差值小于8（41-48），就会再追加16字节到64字节。这说明malloc分配地址，是从最小的32字节开始，每次最小增加量为16倍数，且最后的8字节是不能用的

1. **相邻两次 `malloc` 得到的空间是否是连续的？**

通常情况下，相邻两次调用 `malloc` 得到的内存空间并不是连续的。`malloc` 分配内存时，系统根据当前可用内存块的情况进行分配，可能会从不同的内存区域中分配空间，因此两次 `malloc` 分配的内存地址可能不连续。

即使两次分配请求的大小相同，操作系统或内存管理器为了避免内存碎片化，通常不会将它们分配在相邻的内存地址上。甚至在内存池中，内存块之间可能插入了用于内存管理的元数据或用于对齐的填充字节。

2. **`malloc` 分配的实际内存大小是否就是你请求的大小？**

通常情况下，`malloc` 分配的实际内存大小可能大于你请求的大小，原因如下：

- **内存对齐**：为了满足硬件对内存访问的对齐要求，分配的内存大小通常会被调整为某个倍数（如 8 字节或 16 字节）。比如你请求 7 字节内存，系统可能会分配 8 字节或更多。
  
- **额外的元数据**：`malloc` 实现中通常会在内存块的前面或后面存储一些元数据，用于记录内存块的大小、分配状态等信息。这些元数据占用了额外的字节。

由于这些原因，`malloc` 分配的实际内存块通常大于或等于你请求的大小。你只能安全使用请求的大小范围内的内存，而不应该访问超出请求范围的部分。

3. **`malloc(0)` 会得到什么结果？**

当你调用 `malloc(0)` 时，行为取决于具体的实现：

- **标准允许两种行为**：C 标准允许 `malloc(0)` 返回 `NULL` 或者返回一个有效的指针，但你不能解引用这个指针。如果返回了有效指针，尽管指向了一段大小为 0 的“内存块”，但你不能通过它进行任何有意义的数据访问。

- **常见实现行为**：在实际使用中，大多数 C 库实现中 `malloc(0)` 会返回一个非 `NULL` 的有效指针，但这个指针不能被用于存储数据，只能用来调用 `free`。这种实现可以避免因调用 `malloc(0)` 而引发 `NULL` 相关的特殊处理。

无论是哪种情况，调用 `malloc(0)` 不会导致分配任何可用的内存，返回的结果通常只能用于形式上的内存管理操作。
